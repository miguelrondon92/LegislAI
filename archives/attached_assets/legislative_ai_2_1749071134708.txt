# AI Legislative Analysis Platform Development Prompt

## Core Vision
Build a complete AI-powered legislative analysis platform with an MCP (Model Context Protocol) server backend that democratizes understanding of complex congressional bills. The system should instantly parse, categorize, and evaluate legislation while providing personalized insights based on user policy preferences.

## Technical Architecture Requirements

### MCP Server Backend
- Implement a lightweight MCP server that exposes modular tools for legislative analysis
- Each capability should be exposed as a discrete, API-like tool that can be easily integrated into AI agents or interfaces
- Tools should include: bill parsing, section categorization, stakeholder mapping, policy alignment scoring, and alert generation
- Use modern Python framework (FastAPI recommended) with proper async handling
- Include comprehensive error handling and logging

### Core Functionality Tools
1. **Bill Parser Tool**
   - **Input**: Bill number/ID or Congress API URL
   - **Cache Check**: First check if bill already exists in database with current version hash
   - **Process**: If not cached, fetch from api.congress.gov, store full text with metadata
   - Extracts structured data: sections, subsections, amendments, funding allocations
   - **Storage**: Saves parsed structure and raw text for future reference
   - Returns standardized JSON format with full provenance tracking

2. **Policy Categorizer Tool**
   - **Cache Check**: Look for existing categorization analysis by bill ID and analysis hash
   - **Incremental Processing**: For amended bills, only categorize new/changed sections
   - Uses LLM to categorize bill sections into policy domains (healthcare, environment, economy, etc.)
   - **Storage**: Saves categorization results with confidence scores and reasoning
   - Tags sections with confidence scores and reasoning

3. **Stakeholder Mapper Tool**
   - **Cache Check**: Verify if stakeholder mapping exists for current bill version
   - Maps bill sections to affected stakeholder groups using cached analysis when available
   - **Storage**: Persists stakeholder mappings with impact assessments
   - Cross-references with historical lobbying data patterns

4. **Alignment Scorer Tool**
   - **Cache Check**: Look for existing user-bill alignment scores in database
   - **Smart Recomputation**: Only recalculate if user profile or bill content changed
   - Accepts user policy profiles (JSON format with weighted preferences)
   - **Storage**: Caches alignment scores and detailed reasoning for each user-bill pair
   - Generates detailed explanations for alignment/conflict reasoning

5. **Alert Generator Tool**
   - **Reference Stored Analysis**: Uses cached categorization and alignment data
   - Creates prioritized alerts based on stored policy conflicts or alignments
   - **Historical Context**: References past bill analyses for trend identification
   - Includes actionable insights and contact information for relevant representatives

### User Interface Components
- Clean, modern web interface for exploring bill analysis
- User profile creation for policy preferences (sliders, weighted categories)
- Interactive bill viewer with section-by-section breakdowns
- Dashboard showing personalized alerts and trending legislation
- Comparison tools for multiple bills or versions

### Data Integration
- **Primary Data Source**: https://api.congress.gov/ for real-time congressional bill data
- Implement comprehensive Congress API client with endpoints for:
  - Bill search and retrieval (`/bill/{congress}/{billType}/{billNumber}`)
  - Bill text in multiple formats (`/bill/{congress}/{billType}/{billNumber}/text`)
  - Bill actions and status updates (`/bill/{congress}/{billType}/{billNumber}/actions`)
  - Committee information (`/committee`)
  - Member information (`/member`)
  - Amendment tracking (`/amendment`)
- Support for uploading custom legislative documents as fallback
- Historical bill database populated from Congress API for trend analysis
- Optional integration with lobbying disclosure data from senate.gov

### Analysis Storage & Caching Architecture

**Database Schema Design**
```sql
-- Bills table with full text and metadata
CREATE TABLE bills (
    id UUID PRIMARY KEY,
    congress_id VARCHAR(50) UNIQUE,
    bill_number VARCHAR(20),
    title TEXT,
    full_text LONGTEXT,
    last_updated TIMESTAMP,
    version_hash VARCHAR(64),
    status VARCHAR(50),
    sponsors JSONB,
    committees JSONB
);

-- Stored analysis results
CREATE TABLE bill_analyses (
    id UUID PRIMARY KEY,
    bill_id UUID REFERENCES bills(id),
    analysis_type VARCHAR(50), -- 'categorization', 'stakeholder_mapping', etc.
    analysis_data JSONB,
    created_at TIMESTAMP,
    llm_model VARCHAR(50),
    analysis_hash VARCHAR(64)
);

-- Section-level analysis for incremental updates
CREATE TABLE bill_sections (
    id UUID PRIMARY KEY,
    bill_id UUID REFERENCES bills(id),
    section_number VARCHAR(20),
    section_text TEXT,
    section_hash VARCHAR(64),
    analysis_data JSONB,
    last_analyzed TIMESTAMP
);

-- User alignment scores (cached)
CREATE TABLE user_alignments (
    id UUID PRIMARY KEY,
    user_id UUID,
    bill_id UUID REFERENCES bills(id),
    alignment_score INTEGER,
    detailed_scores JSONB,
    calculated_at TIMESTAMP
);
```

**Smart Caching Strategy**
1. **Bill Text Caching**: Store full bill text with version hashing to detect changes
2. **Analysis Result Caching**: Persist all AI-generated analysis to avoid re-computation
3. **Incremental Processing**: Only analyze changed sections when bills are amended
4. **User Score Caching**: Store personalized alignment scores for frequently accessed bills
5. **Search Index Caching**: Pre-computed search indices for fast bill discovery

**Cost Optimization Logic**
- Check analysis cache before making AI API calls
- Use text diffing to identify changed sections in bill amendments  
- Batch similar analysis requests to optimize API usage
- Implement analysis expiry for time-sensitive content
- Priority queue for high-value analyses (trending bills, user-requested)
